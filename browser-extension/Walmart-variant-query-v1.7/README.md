# Walmart 商品变体查看器

独立 Chrome／Edge 插件，不需要项目后端。

- **整款查询（默认）**：一次读取整款变体的下单上限、在售状态与价格，可导出 CSV。
- **当前 Item**：查看当前变体的下单上限、页面字段和本页变体列表，可导入历史 CSV 对照。
- **逐个打开变体**：在当前标签页依次打开变体，入口位于「整款查询」底部。

## 界面（v1.7）

- 使用标签切换「整款查询」和「当前 Item」。切换商品后，弹窗会标明已保存的整款任务来自哪个商品。
- 查询进度、导出和重试在矩阵上方。结果区显示已读取数量，未返回上限的变体在矩阵中单独标记。
- 宽矩阵可以横向滚动，保留表头和首列。矩阵图例区分缺货、零件、未返回上限和暂无结果。
- 当前 Item 支持在表格中筛选颜色、尺码、ID 和在售状态。导入历史 CSV 后可并排核对历史值。
- 主题跟随系统设置。可用方向键切换标签并通过 Tab 访问表格及按钮。

## 安装

1. 如果收到的是 ZIP，先解压到一个保留的位置。安装目录里应当能直接看到 `manifest.json`。
2. 在 Chrome 地址栏打开 `chrome://extensions`，或在 Edge 打开 `edge://extensions`，开启「开发者模式」。
3. 点「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的文件夹。安装后可从扩展菜单固定到工具栏。
4. 打开 Walmart 美国站商品页，等页面加载后点击插件。

已经安装旧版时：解压新版到新的文件夹，在扩展管理页移除旧版后加载新版文件夹；或者用新版文件替换旧版所在目录后，在扩展管理页点击该插件的「重新加载」。

## 整款速查怎么用

1. 在任意一个变体的商品页点插件，在「整款查询」点「开始查询」。
2. 插件从入口页的 `product.variantProductIdMap` 拿到**全量变体清单**（key 自带维度与尺码），然后对每个 `productId` 在页面上下文里做一次同源 `fetch`，拿服务端渲染的 HTML，切出 `<script id="__NEXT_DATA__">`，只取需要的字段。
3. 全程不导航、不渲染页面，所以 120 个变体只需几分钟；可以在弹出窗里看到进度、暂停、继续、停止。**关掉弹窗任务仍会继续**，再点开插件会接着显示。
4. 结束后可「下载 CSV」或「复制明细」；失败的变体列在「查看失败明细」里，可以点「重试失败项」只重跑失败的那部分。

### KPI 怎么读

- **下单上限合计**：整款所有变体 `orderLimit` 之和。**这是页面下单上限，不是后台真实库存，也不是销量**。
- **变体 SKU**：已读到的 SKU 数 / 入口页给出的变体总数。
- **在售 / 缺货**：按 `availabilityStatus` 是否等于 `IN_STOCK` 分。
- **单 SKU 均值**：合计 ÷ 已读 SKU 数。
- 提示区列出上限 1～9 件、在售但上限为 0、未返回上限等情况。合计仅累加已返回的数值。均值仍以已读取的变体数为分母。

### CSV 列（14 列，与命令行 skill 一致）

`variant_dim, variant_value, variant_label, size, usItemId, productId, orderLimit, maxOrderQuantity, orderMinLimit, availabilityStatus, price, wasPrice, isPriceReduced, seller`

- `variant_label` 优先取页面的 `variantCriteria` 展示名，取不到时按 slug 美化（把 `darkgreenstripe` 变成 `Darkgreenstripe`），**这种兜底标签不是 Walmart 官方色名**。
- `orderLimit` 缺失不会写成 0，而是留空；`maxOrderQuantity` 在缺货 SKU 上通常整段不存在，也留空。
- CSV 带 UTF-8 BOM，Excel 直接双击打开不乱码。

## 口径与已知坑

- 前台限购 ≠ 实际库存。`orderLimit` 只是当前卖家与配送条件下的单笔上限，结账不保证能买到该数量。
- `availableQuantity` 在 Walmart PDP 里**恒为 null**，插件不展示、也不推测。
- `isLowInStock` 不可靠，插件不使用；「告急」是按 `orderLimit < 10` 自己算的。
- `maxOrderQuantity` 只在在售（有发货选项）的 SKU 上出现；缺货 SKU 没有该字段属于正常，不是抓取失败。
- 变体维度**不一定是 `actual_color`**，实测还有 `pattern`；值是整串 slug，可能带 `01`、`A1` 这类前缀，前缀不能当批次或定价依据。
- 颜色取值可能是 Walmart 标准色卡（如 `Beige`），展示名在 `variantCriteria`，两者本来就可能不一致。
- 同一款可以「部分 SKU 标降价、部分不标」，且现价完全一致；插件逐 SKU 呈现，缺失显示「—」。
- 同款可以有多档价，且差档可能按色、按码、按单个 SKU 或完全无法解释；不要拿入口 SKU 的价格或降价状态概括整款。

## 旧模式（逐个打开变体）

在「整款查询」展开「逐个打开变体」，点「开始逐个查询」。它会在当前标签页依次导航 `/ip/{usItemId}`，每次随机等 1～20 秒，读当前页的发货 `orderLimit` / `maxOrderQuantity` / `availableQuantity`。可暂停、继续、停止并复制结果。遇到异常跳转、读取失败、超时或标签关闭时停止。

两种模式的差别只有「取数通道」：整款速查用同源 `fetch` 读 HTML 文本；旧模式用导航让页面自己去请求。数据源都是同一个 PDP。

## 隐私与合规

插件不加购物车、不下单、不上传任何数据；进度和结果只存在浏览器扩展的本地存储里，弹窗关闭后仍在，可在下次打开时查看或导出。

批量自动采集可能与 Walmart 的访问条款冲突，同源请求和随机间隔都不保证合规或避免风控。使用前请确认自身权限；遇到验证页时插件会停止，不尝试绕过。

## 开发验证

```bash
node --test bulk.test.mjs
```

测试用本地构造的 `__NEXT_DATA__` 片段，不访问 Walmart。覆盖：变体 key 的通用解析（含 `pattern` 维度、无尺码 key）、SSR HTML 解析（字符串型 `orderLimit`、缺货无 `maxOrderQuantity`、403 与验证页的错误归因）、汇总与矩阵、CSV 的 BOM/列数/引号转义。

改完代码后在扩展管理页点「重新加载」。可在有权访问的商品页验证当前 Item、整款进度、结果矩阵及 CSV 导出。
